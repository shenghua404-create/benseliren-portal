# 本色丽人门户网站设计规格

日期：2026-05-15

## 背景

本色丽人需要一个高端护肤品公司门户网站。公司业务同时包含护肤品 OEM/ODM 代加工和自有产品。首版目标是做一个可快速上线的单页门户，优先服务国内护肤品牌方和创业品牌客户。

当前没有现成 logo、产品图、工厂图、证书或品牌素材。首版会使用统一风格的设计化视觉和可替换素材位置，不虚构真实资质、证书编号或无法验证的生产能力。

## 目标

- 建立“高端、可信、温和、专业”的护肤品公司形象。
- 让国内创业品牌方快速理解本色丽人的代加工服务、合作流程和咨询入口。
- 展示本色丽人自有产品线，让公司不只是工厂形象，也具备品牌气质。
- 首版可部署到 GitHub Pages，后续可扩展成多页官网。

## 目标用户

主要用户是国内护肤品牌方、创业品牌和渠道方。他们关心：

- 能否把产品想法转成样品和可量产方案。
- 是否提供配方开发、打样、包材建议、生产交付等完整协作。
- 合作流程是否清晰，下一步是否容易咨询。
- 官网是否体现高端护肤品牌的品质感。

## 网站范围

首版为单页门户，不做多页路由。

页面包含：

1. 顶部导航
2. 首屏品牌主张
3. OEM/ODM 代加工与自有产品双入口
4. 代加工能力模块
5. 自有产品系列模块
6. 合作流程模块
7. 品牌理念模块
8. 联系咨询表单

首版不包含：

- 真实后端表单提交。
- 在线支付、会员系统、后台管理。
- 多语言版本。
- 未经确认的真实工厂资质、合作案例、检测报告或专利信息。

## 信息架构

顶部导航：

- 本色丽人
- 代加工服务
- 产品系列
- 合作流程
- 联系咨询

首屏：

- 标题：以东方肤感与现代配方，共创你的护肤品牌
- 副文案：本色丽人为新锐护肤品牌提供配方开发、样品打样、包材建议与成品交付服务，同时打造温和、细腻、稳定的自有护肤产品线。
- 主按钮：开启品牌共创
- 次按钮：了解代加工流程

双入口：

- OEM/ODM 代加工：面向品牌方，突出配方、打样、包材、交付。
- 本色丽人自有产品：突出温和护肤、东方肤感和产品系列。

代加工能力：

- 配方方向建议
- 样品打样沟通
- 包材与视觉建议
- 成品生产交付

产品系列：

- 舒缓修护
- 补水保湿
- 亮肤焕采
- 抗初老护理

合作流程：

1. 需求沟通
2. 方案建议
3. 样品确认
4. 生产交付

咨询表单字段：

- 姓名
- 品牌阶段
- 需求类型
- 联系方式
- 留言

表单提交后显示前端成功状态，并提示通过页面展示的联系方式进一步沟通。真实数据接收后续再接入后端或第三方表单服务。

## 视觉方向

采用“东方肤感美学 + 护肤品牌共创工厂”的方向。整体要有东方美学记忆点，但不能牺牲代加工转化效率。

视觉特征：

- 深暖棕黑首屏底色，建立高级感。
- 玫瑰陶土色、柔和玉绿色和少量香槟金作为辅助色。
- 大留白、低饱和、温和光感。
- 产品罐、精华瓶、质地纹理和实验室场景使用统一设计化视觉。
- 版式避免传统工厂网站的拥挤信息堆叠。
- 不使用夸张功效、虚假背书或不可验证数据。

页面氛围：

- 专业但不冰冷。
- 高端但不奢侈化。
- 有品牌故事感，同时让创业品牌知道如何开始咨询。

## 技术方案

使用 React + Vite 构建静态单页网站。

理由：

- 适合响应式单页门户。
- 后续可扩展多页路由和组件化模块。
- 表单状态、导航滚动、动效和交互实现稳定。
- 可构建为静态文件并部署到 GitHub Pages。

建议结构：

- `src/App.jsx`：页面组合入口。
- `src/components/`：导航、首屏、服务模块、产品模块、流程、咨询表单等组件。
- `src/data/`：页面文案、产品系列、服务能力数据。
- `src/styles/`：全局样式和设计 token。
- `public/` 或 `src/assets/`：后续替换的图片资源。

## 部署方案

优先使用 GitHub Pages。

流程：

1. 本地初始化 Git 仓库。
2. 创建 React + Vite 项目。
3. 配置静态构建与 GitHub Pages 路径。
4. 本地运行并验证桌面、移动端布局。
5. 提交代码。
6. 用户完成 GitHub 登录或提供远程仓库地址后，推送到 GitHub。
7. 开启 GitHub Pages，从构建产物部署站点。

如果使用 GitHub Actions 部署，需要仓库权限和 GitHub 登录状态。若用户暂未登录，则先完成本地项目、构建配置和提交，推送与 Pages 开启步骤等待授权。

## Vercel、Netlify 与 GitHub Pages 区别

GitHub Pages：

- 最适合简单静态官网。
- 成本低，和 GitHub 仓库直接绑定。
- 对表单后端、预览部署和复杂路由支持较弱。

Vercel：

- 对 React、Next.js 和预览部署体验更强。
- 适合后续要做动态功能、SSR 或团队协作预览的项目。
- 需要 Vercel 账号授权。

Netlify：

- 静态站能力强，表单、重定向、函数等功能较开箱。
- 适合需要无后端表单接收或轻量 serverless 的营销站。
- 需要 Netlify 账号授权。

首版门户选择 GitHub Pages 足够；后续如果要真实接收表单，可以再接入后端、第三方表单服务，或迁移到 Netlify。

## 响应式与可访问性

- 桌面端首屏保留强品牌视觉和双 CTA。
- 移动端导航简化为可点击菜单或纵向导航。
- 按钮、表单输入和链接具备清晰 hover/focus 状态。
- 文案和按钮不依赖图片渲染，保持 SEO 和可访问性。
- 图片均提供可替换结构和描述。

## 测试与验收

实现后需要验证：

- `npm run build` 成功。
- 桌面端首屏、模块节奏、表单和导航正常。
- 移动端无横向溢出、文字不遮挡、按钮可点击。
- 表单提交后展示前端成功状态。
- 构建产物适合 GitHub Pages 静态部署。

视觉验收点：

- 保留东方美学方向。
- 首屏品牌调性足够高端。
- 代加工服务与合作流程足够清楚。
- 自有产品模块不会压过代加工主转化。
- 没有虚构资质、假证书、假案例或夸张功效。
